# MediFlow AI — 4-Member Project Division

## Project Overview

**MediFlow AI — Intelligent Channeling, E-Prescription & Pharmacy Management System**

A full-stack production-style application built around a channeling center workflow. Patients book doctor appointments, receptionists verify payments and confirm appointments, doctors conduct consultations and create e-prescriptions with AI-assisted medication availability checking, pharmacists process prescriptions and calculate medicine costs, pharmacy inventory is intelligently monitored, suppliers receive automated restocking requests, and patients can track prescriptions, orders, and provide pharmacy feedback — while human professionals remain responsible for all critical medical and operational decisions.

> **Key Design Change:** Patients do **not** upload prescriptions themselves. Prescriptions are generated by the doctor inside the channeling workflow during the patient consultation.

### Technology Stack

| Layer | Technology |
|---|---|
| Mobile | Flutter / Dart |
| Web | React / React Router |
| Backend API | ASP.NET Core Web API / C# |
| Database | PostgreSQL / EF Core |
| Auth | JWT / Role-based |
| Agentic AI | Agent orchestration framework (LangGraph / MS Agent Framework / Google ADK) |
| Docs | Swagger / OpenAPI |
| CI/CD | GitHub Actions |

### Core Principle

> Every member owns a **complete vertical business component** — database tables, API endpoints, UI screens, an AI agent (or orchestrator), tests, and documentation. No member is "just backend" or "just frontend."

### AI Agent — Appointment Intelligence Agent

**Purpose:** Assist with intelligent appointment management — analyzing doctor availability, identifying suitable slots, considering appointment load, and providing scheduling recommendations.

**Input:** Patient preferences (doctor, date, time)

**Output:**

```json
{
  "doctorId": 5,
  "doctorName": "Dr. Silva",
  "preferredTime": "Evening",
  "recommendations": [
    { "time": "5:30 PM", "status": "AVAILABLE", "load": "LOW" },
    { "time": "6:00 PM", "status": "AVAILABLE", "load": "MEDIUM" },
    { "time": "6:30 PM", "status": "FULLY_BOOKED", "load": "FULL" }
  ],
  "conflicts": [],
  "bestRecommendation": "5:30 PM"
}
```

**Tools Used:**

| Tool | Purpose |
|---|---|
| `check_doctor_availability()` | Check doctor's schedule for open slots |
| `analyze_appointment_load()` | Analyze appointment density per time slot |
| `detect_scheduling_conflicts()` | Detect double-bookings or overlaps |
| `recommend_appointment_slot()` | Rank and recommend best available slots |

**Safety Rules:**

- The final booking remains controlled by the system/receptionist workflow
- Must NOT auto-book appointments without patient confirmation
- Must base recommendations on actual schedule data only
- If no slots available → clearly report: *"No available slots for the selected date"*

### AI Evaluation Metrics — Appointment Intelligence

| Metric | Description |
|---|---|
| Recommendation Accuracy | % of recommended slots that are genuinely available |
| Scheduling Conflict Reduction | Reduction in double-bookings after AI analysis |
| Appointment Utilization | % of recommended slots that were actually booked |

### AI Agent — Medication Intelligence Agent

**Purpose:** Search medicine information, check pharmacy inventory for requested quantities, identify unavailable medicines, find potentially available alternatives, and provide medicine availability information to the doctor. This replaces the previous prescription-extraction agent because the doctor now creates the prescription directly.

**Input:** Medicine name/search query + requested quantity

**Output:**

```json
{
  "medicine": "Amoxicillin 500mg",
  "availability": true,
  "currentStock": 45,
  "requestedQuantity": 20,
  "result": "SUFFICIENT_STOCK",
  "alternatives": []
}
```

**When Unavailable:**

```json
{
  "medicine": "Medicine X",
  "availability": false,
  "currentStock": 0,
  "requestedQuantity": 15,
  "result": "UNAVAILABLE",
  "alternatives": [
    { "name": "Medicine B", "available": true, "stock": 30 },
    { "name": "Medicine C", "available": false, "stock": 0 }
  ],
  "aiNote": "This medicine is unavailable. The following medicines are available in the pharmacy."
}
```

**Tools Used:**

| Tool | Purpose |
|---|---|
| `search_medicine()` | Search medicine by name in the pharmacy database |
| `check_medicine_availability()` | Check stock quantity for a specific medicine |
| `check_requested_quantity()` | Validate if requested quantity is available |
| `find_alternative_medicines()` | Find available alternatives for unavailable medicines |
| `calculate_inventory_info()` | Provide inventory-related analytics |

**Safety Rules:**

- The AI must NOT independently replace a prescribed medicine
- The AI can provide information: *"This medicine is unavailable. The following medicines are available in the pharmacy."*
- The doctor makes the final clinical decision on alternatives
- Must NOT invent medicine availability data
- If database unavailable → safe failure with message

### Safety / Urgency Detection

The agent identifies potentially urgent symptoms and avoids simply recommending a normal channeling appointment.

```text
⚠️ URGENT MEDICAL ATTENTION RECOMMENDED

Your symptoms (severe chest pain, difficulty breathing)
may indicate a condition requiring immediate medical care.

Please seek emergency medical attention rather than
waiting for a regular channeling appointment.

This is not a diagnosis. This is a safety recommendation.
```

**Urgency Trigger Examples:**

| Symptom Pattern | Urgency Level |
|---|---|
| Severe chest pain + difficulty breathing | 🔴 EMERGENCY |
| Sudden severe headache + vision loss | 🔴 EMERGENCY |
| High fever + confusion | 🟠 HIGH |
| Persistent bleeding | 🟠 HIGH |
| Mild joint pain for weeks | 🟢 NORMAL |
| Skin rash, no other symptoms | 🟢 NORMAL |

**Tools Used:**

| Tool | Purpose |
|---|---|
| `extract_symptoms()` | NLP-based extraction of symptoms from free text |
| `classify_symptoms()` | Classify extracted symptoms into medical categories |
| `rank_specialties()` | Rank medical specialties by relevance with confidence scores |
| `detect_urgency()` | Detect potentially emergency/urgent symptoms |
| `check_doctors_by_specialty()` | Find available doctors in recommended specialty |
| `generate_explanation()` | Generate human-readable explanation for recommendation |

**Safety Rules:**

- Must NOT diagnose the patient — only recommend a **specialty**
- Must NOT replace professional medical judgment
- Must always display: *"This is a specialty recommendation, not a diagnosis"*
- Must detect and flag potentially urgent symptoms with safety warnings
- Must NOT encourage patients with emergency symptoms to wait for a normal appointment
- If symptom analysis is uncertain → recommend General Medicine with explanation
- Must base doctor availability on actual schedule data only
- If NLP/LLM unavailable → safe failure with message: *"Unable to analyze symptoms. Please search for a doctor manually."*

## 10. Human-in-the-Loop AI Architecture

AI should **assist** rather than independently make medical decisions. The following decisions **must** remain with humans:

| Decision Point | Human Authority | AI Role |
|---|---|---|
| Appointment Verification | Receptionist verifies appointment + payment | AI recommends slots, detects conflicts |
| Specialist Selection | Patient selects doctor and makes booking decision | AI recommends specialty based on symptoms, not a diagnosis |
| Prescription | Doctor decides what medicine to prescribe | AI checks availability, provides info |
| Alternative Medicine | Doctor decides if alternative is clinically appropriate | AI lists available alternatives |
| Pharmacy Fulfillment | Pharmacist verifies and processes medicine order | AI calculates prices, checks inventory |
| Supplier Restocking | Supplier approves/rejects restock request | AI recommends restock quantities |

This creates a strong **Human-in-the-Loop Agentic AI Architecture**.

## 22. Safe Failure Scenarios

Each member must handle failures gracefully within their component:

| Scenario | Owner | Safe Response |
|---|---|---|
| No doctor slots available | Member 1 | Report *"No available slots for the selected date"* |
| Payment verification fails | Member 3 | `PAYMENT_VERIFICATION_FAILED` — do not verify appointment |
| Medicine not found in database | Member 2 | Report *"Medicine not found"* with search suggestions |
| Medicine stock insufficient | Member 2 | Report exact available quantity, suggest alternatives |
| No alternatives available | Member 2 | Report *"No alternatives available"* — doctor provides handwritten prescription |
| Inventory data unavailable | Member 3 | `INVENTORY_CHECK_FAILED` — safe failure with message |
| Low-stock detection error | Member 3 | Log error, do NOT auto-generate restock requests |
| Supplier API failure | Member 4 | `SUPPLIER_REQUEST_FAILED` — record reason |
| Symptom analysis fails | Member 4 | *"Unable to analyze symptoms. Please search for a doctor manually."* |
| NLP/LLM unavailable | Member 4 | Fallback to manual doctor search — safe degradation |
| Urgency detection uncertain | Member 4 | Default to showing safety warning — err on side of caution |

## 27. Critical Group Working Rules

### ✅ DO

- Each member owns a **full vertical slice** (DB → API → UI → AI → Tests → Docs)
- All members work in the **same GitHub repository**
- Use **feature branches** and **pull requests** with code review
- Every member must have **visible, meaningful Git contributions**
- Share the `AppDbContext` — register your entities in one shared context
- Communicate when your component's API contract changes
- Write tests for your own components
- Document your own Swagger endpoints
- Ensure human-in-the-loop at every critical decision point

### ❌ DON'T

- Don't divide as: *Member 1 = Backend, Member 2 = React, Member 3 = Flutter, Member 4 = AI*
- Don't commit secrets, API keys, connection strings, or JWT secrets
- Don't create fake/back-filled Git contribution history
- Don't add unnecessary features before the core workflow is stable
- Don't let agents make unsupported medical decisions
- Don't let AI independently replace prescribed medicines
- Don't expose stack traces or internal errors to users
- Don't allow patients to upload prescriptions (prescriptions are doctor-generated)
